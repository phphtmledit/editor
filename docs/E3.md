## Import

`.html`, `.htm` and `.docx` are selected by case-insensitive file extension,
not by the unreliable browser MIME string. Exactly 5 MiB (5,242,880 bytes) is
accepted; one byte more is rejected before the file is read or Mammoth is
loaded. Read and conversion failures produce visible messages and leave the
document unchanged.

A full HTML document is reduced to its editable `body` fragment. An input that
is already a fragment stays byte-for-byte untouched until TinyMCE receives it.
DOCX conversion is loaded dynamically only after extension/size validation and
a successful binary read. Mammoth output then passes through the default
cooperative cleaner before it can be written. Conversion warnings are bounded
to ten messages and 500 Unicode characters per message; additional warnings
are counted without allowing unbounded output.

The import UI yields two animation frames before parsing so its busy state can
paint. File drop is handled both by the outer workspace, including CodeMirror,
and inside TinyMCE's iframe document. Only file payloads are intercepted;
ordinary text dragging remains native editor behavior. Multiple files,
unsupported extensions and oversized inputs are stopped with explicit errors,
including prevention of accidental browser navigation on a file drop.

Every asynchronous import captures the authoritative HTML before reading or
conversion. Immediately before applying its result, the active editor is
flushed again and compared with that snapshot. If the user edited either panel
in the meantime, the result is discarded with a visible stale-result message.

## Export and clipboard

HTML download flushes the active editor, reads the visual editor's canonical
fragment and wraps it in a minimal HTML5 document with doctype, UTF-8 charset
and viewport metadata. The object URL is revoked after the synthetic download
click rather than before the browser has consumed it.

“Copy HTML” copies the markup string; “Copy text” uses TinyMCE's text
projection. The asynchronous Clipboard API is invoked before the first
`await`, preserving transient user activation in an iframe. If permission or
iframe delegation is absent, a temporary textarea plus `execCommand('copy')`
is used. Temporary DOM, focus and scroll position are restored in `finally`,
and success is reported only when one of the two paths actually succeeds.

## Drafts, sample and new document

The versioned local draft record stores `{ html, savedAt }` under
`phphtmledit.draft.v1`. Autosave starts after editor initialization, runs every
3 seconds, skips unchanged source and measures the raw source as UTF-8. The
limit is exactly 1 MiB (1,048,576 bytes). If the current document becomes
larger, the last valid stored draft is retained, a warning is shown, and saving
resumes after the document becomes small enough. Storage and source-read
failures are visible rather than fatal. `pagehide` performs a final synchronous
storage attempt; the mass-operation undo stack is never serialized.

A valid draft is loaded before TinyMCE and CodeMirror are constructed. The
source panel receives the exact raw string and eager highlighting immediately;
TinyMCE may hold its normalized visual projection. That projection is seeded
into the E1 synchronizer so normalization remains deferred until focus moves
to the visual panel. Restoration does not create a mass-undo entry.

“Пример” loads a small product-owned dirty HTML constant, not a test fixture.
“Новый документ” asks for confirmation, while “Начать заново” on a restored
draft is the explicit discard action and does not ask twice.

## Mass-write boundary

E3 does not reuse the E1 synchronization writer for whole-document changes.
HTML/DOCX import, the sample and a new document all call the existing E2 mass
document controller. Before each write, the exact authoritative snapshot enters
the one shared ten-entry stack; both TinyMCE and CodeMirror native histories are
then reset. The single application Undo button therefore restores the latest
cleaning, replacement or E3 whole-document operation in chronological order.

Export, clipboard and draft autosave are read paths and do not create undo
entries. Initial draft restoration happens before editor construction and is
also not a mass operation.

### Worker HAR wire-size limitation

The regular-expression Worker crosses the page and Worker CDP sessions. Chrome
provides a real request/response/data/`Network.loadingFinished` lifecycle and
the complete 1,655-byte decoded size, but does not expose a byte-accurate gzip
body/header split across those sessions. The HAR therefore keeps one
non-synthetic Worker entry with `headersSize: -1`, `bodySize: -1`, no invented
`content.compression`, and the observed encoded length as an implementation
detail. The four budgets do not use HAR wire sizes: they recompress the exact
manifest-bound `dist` files with gzip-9 and Brotli-11.

## Known limits and E6 follow-up

- DOCX/PDF export is Phase 2 and is deliberately absent from MVP E3.
- Automated DOCX coverage proves the accepted fixture and Wingdings behavior;
  semantic quality on heterogeneous real documents remains a human E6 check.
- Current clipboard-cleaning coverage was captured from Microsoft Word for the

  real fixture and manual acceptance path.
- Real iOS/Android, cross-browser, cross-origin iframe clipboard and host-page
  Lighthouse checks remain E6/human work under `AGENTS.md` §11.
