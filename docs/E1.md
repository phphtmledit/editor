Date: 2026-08-13. Repository: <https://github.com/phphtmledit/editor>.

## Implemented product skeleton

- The deployable `index.html` initializes self-hosted TinyMCE 8.8.2 and a
  CodeMirror 6 source editor. The E0 diagnostic HTML moved to
  `src/e0/index.html`; `vite --mode e0` substitutes it without adding fixtures
  or Mammoth to the product graph.
- Desktop uses two simultaneous editor regions and a pointer-captured,
  keyboard-operable separator. Its value is exposed through separator ARIA and
  is bounded to 30–70%; arrows move by 2%, Shift+arrow by 10%, Home/End select
  the bounds.
- At widths below 900 px the regions become a `tablist` with Visual/Code tabs;
  the inactive region is genuinely hidden. A 390×844 Chromium pass confirmed
  one visible panel, a hidden splitter and arrow-key tab navigation.
- The source editor includes line numbers, wrapping control, character count,
  folding, HTML syntax highlighting, pair matching, autocomplete and
  `Ctrl/Cmd+F` search/replace. The HTML grammar and highlighting are present in
  the first render; search key bindings are also synchronous. Only
  autocomplete, the folding gutter and pair matching load on first source
  focus without recreating `EditorView`. The activation is lazy; common
  `@codemirror/language` implementation may be deduplicated into the cold entry.
- The eager language is built on the bare `@lezer/html` parser. It deliberately
  does not configure nested JavaScript/CSS grammars for `<script>` and `<style>`.
  The public `html({ nestedLanguages: [] })` API cannot express this: an empty
  list falls back to the preconfigured nested language and `html()` also adds
  JavaScript/CSS support.
- The UI has a loading skeleton, visible failure state, privacy statement,
  `visualViewport` height tracking, focus styles, coarse-pointer targets and
  reduced-motion handling. Product CSS uses the required `--phe-*` tokens and
  the `#4F46E5` light accent. Final themes and the “About” menu remain E4/E5.

## Synchronization model

Only the focused editor is authoritative. TinyMCE changes use a trailing 300 ms
delay; CodeMirror changes use 500 ms and are accepted only while focus remains
inside the complete source panel, including its search/replace controls. A
focus transfer flushes the outgoing editor immediately, cancels its timer and
changes authority. Revision/token checks reject stale callbacks.

Programmatic writes use a nesting guard and never call either editor's
`focus()`. CodeMirror receives one common-prefix/suffix replacement annotated
outside its local history, so its mapped ranges and scroll position survive.
TinyMCE writes run inside `undoManager.ignore`, preserve iframe scroll and use
its bookmark with a text-offset fallback when normalized DOM nodes no longer
match. Source HTML remains untouched while the source editor owns focus; if
TinyMCE serializes it differently, the normalized projection is adopted only
on transfer to the visual editor and a polite one-time explanation is shown.

The browser pass covered source → visual at 500 ms, visual → source at 300 ms,
focus-switch flush, deferred normalization, no-focus-steal, CodeMirror selection
survival, search/replace authority, wrapping reconfiguration, TinyMCE toolbar
and link-dialog focus, splitter keyboard bounds, mobile tabs and Back/Forward
cache restoration. The final CDP scenario additionally synchronized a non-empty
HTML sample while the visual editor retained focus and observed eight highlighted
CodeMirror spans before the first source focus; the lazy chunk was still absent.
The console remained empty. No automated module suite is claimed: `AGENTS.md`
introduces Vitest with the cleaning module in E2.

DOCX/golden fixtures, Tiny Cloud domains, caches and service workers are absent.
The cumulative capture contains every cold URL and exactly one additional JS
asset. Assertions are recorded in `reports/network-e1-har-result.json`; current
file/hash/size rows are in `reports/size-e1-result.json`. Historical E0 evidence
was not overwritten.

code. Applying the previously measured Mammoth contribution (123,940 B gzip /
102,270 B brotli) to the current cumulative build projects 752,282 / 635,074 B,
already 2,282 / 5,074 B over the 750,000/630,000 ceilings. The existing
diagnosis remains the plan: remove the dead Bluebird and xmlbuilder paths and
avoid pulling all of Underscore. `dingbat-to-unicode` stays because real Word
documents rely on its Wingdings/Symbol conversion.
